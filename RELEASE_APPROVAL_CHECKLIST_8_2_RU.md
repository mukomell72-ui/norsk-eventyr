# Norsk Eventyr 8.2 — выпускной акт (подготовка, не разрешение на публикацию)
**Дата:** 9 октября 2026 г.  **Ветка:** `feature/8.2.0-placement-calibration`  **PR:** #38 (черновой).
**ОСНОВНОЙ САЙТ, main и действующая Supabase не изменены.**

## Что подготовлено
- Сервер: отдельный секрет подписи сессий, контроль входящих запросов, защита авторизованных и административных маршрутов, распределённые лимиты платного AI с отказом при недоступной базе (не бесконтрольный пропуск).
- Облако: staged-migration `SECURITY_8_2_SYNC_PREPARE.sql`, персональная привязка записи, контроль прав, первоначальное присвоение старой записи после предъявления прежнего кода, оптимистическая проверка ревизии, явное удаление облачной копии с подтверждением.
- Окончательное отключение старых анонимных RPC вынесено в `SECURITY_8_2_SYNC_CUTOVER.sql`. Выполняется **только после** запуска и подтверждения новой схемы, иначе ломает старые устройства.
- Автотесты: корректность учебной логики и интерфейса, синхронизации, отрицательные сценарии доступа, проверка SQL в изолированной базе, целостность исходников для Android.
- Руководство по откату и безопасности: `SECURITY_RELEASE_PLAN_8_2.md`.

## Что нельзя автоматически объявить готовым
- **Сервер и БД:** SQL подготовлен, но не применён к действующему проекту. До внедрения требуется резервная копия, тест в независимом окружении, решение о периоде обслуживания, фактическая проверка отката.
- **Vercel Preview:** последний доступный Preview обязан соответствовать одному и тому же SHA с QA/APK. В октябре 2026 наблюдались остановившиеся автоматические развёртывания Preview, поэтому не принимать READY для старого коммита за подтверждение финального RC.
- **Vercel WAF:** необходимо проверить существующие правила в панели проекта и подготовить логирование перед включением блокировки. Читать конфигурацию через доступный API не удалось; считать её работающей без проверки нельзя. Руководство: https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting
- **Платный AI:** учёт количества запросов защищает от превышения числа операций, но не ограничивает прямую сумму счёта. Настроить отдельные лимиты затрат/оповещения у AI-провайдера и проверить месячный прогноз при целевой аудитории.
- **Supabase Auth:** официальный Security Advisor сообщил `auth_leaked_password_protection` как предупреждение. Включение требует настройки действующего сервиса отдельно.
- **Юридические права пользователя:** проверить и опубликовать достоверные сведения о контролёре данных, точном сроке хранения, подрядчиках, целях обработки, удалении **всего аккаунта**, а не только облачной копии. Проверить соглашения с процессорами и обслуживание запросов доступа/удаления (Datatilsynet). Это требует проверки реальных настроек и процесса, не может быть подтверждено одним программным тестом.
- **Android:** нынешний APK — debug WebView для частного тестирования. Он **не** является подписанной магазинной сборкой, не подготовлен как AAB для Google Play. Публичный выпуск в магазин потребует отдельной конфигурации пакета, иконок, ключей подписи, политик и сертификации магазина.
- **Обучение:** отзыв пользователя «alt veldig bra» — положительный ручной тест, но не независимая языковая проверка A1–B2 и не доказательство гарантированного результата.

## Требуемая последовательность разрешённого внедрения
1. Пройти QA и Android на **одном финальном SHA**, затем проверить идентичность Preview.
2. Подготовить независимое тестовое окружение/снимок Supabase и проверяемое восстановление. Прогнать SQL двух миграций, два аккаунта, отказ доступа, проверку старого кода, конфликт изменений и удаление.
3. До релиза согласовать с владельцем параметры WAF, расходы AI, юридический текст, процесс удаления аккаунтов и обязательные настройки окружения, в том числе `NE_SESSION_SECRET`.
4. **Только по отдельному явному разрешению** ввести аддитивные SQL миграции, затем согласованно переключить Production на новую версию; сразу после подтверждения новой схемы отозвать права анонимных legacy RPC и проверить запреты.
5. После выпуска выполнить реальный smoke-тест на телефонах; при нарушении сценария восстановить доступ из подтверждённого резервного решения, не отключая без необходимости сохранённый прогресс.

## Решение
**До выполнения пунктов выше — NO-GO.** Этот документ подтверждает работу по подготовке, но не даёт права на слияние ветки, публикацию сайта, магазинный релиз, применение SQL и изменение WAF.

Источники: [Vercel WAF](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting), [Datatilsynet](https://www.datatilsynet.no/), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).
