# Norsk Eventyr 8.3.0 — единый локальный пакет перед публикацией
**Дата подготовки:** 13 октября 2026.
**Статус:** ветка release/8.3.0-local-staging-20261013; **НЕ ОПУБЛИКОВАНА** на production, без изменения работающей 8.2.9. Статус готовности всегда уточняется результатом CI для **последнего** коммита.
**Исходная основа:** PR #53, ветка feature/deeper-lessons-listening-adaptation-20261013. В неё уже входят завершённые изменения из PR #50 (регрессионные проверки), #51 (мобильный микрофон и восстановление прогресса), #52 (методическая программа и инструменты исследования) и все вошедшие ранее в main исправления.

## Включено в технический кандидат 8.3.0
- Курсы A1/A2/B1/B2: 32 существующих подготовленных модуля, без замены их прежних вопросов и ответов.
- 72 подготовленных текста для синтетической аудиоозвучки (прежде было 64). В 8 модулях третья независимая ситуация, по две новые ситуации на каждый уровень A1, A2, B1, B2.
- Дополнительный голос AI на третьей части; текст аудирования появляется по запросу после ответа, а не до него. Темп обычный/медленный.
- Адаптивная Нора: при близко низких результатах по навыкам учитывается число действительных попыток, а не только стартовый балл. Повторы по ошибкам, контроль переноса, защита от ложного повышения уровня сохранены.
- Подготовленные протоколы проверки заданий/озвучки/данных/педагогики, локальные инструменты подсчёта объёма курса и расхождений оценок с двумя экспертами.
- Согласованы APP_VERSION, страница, видимая версия, health endpoint, ссылки на статические файлы и Service Worker 8.3.0. Проверяются старая PWA/новая PWA, холодный запуск и сохранение незавершённого ответа.
- Включены прежние проверки доступа, приватности, импорта, логина, финансовых прав, безопасности SQL и голосового ввода.

## Что сознательно НЕ добавлено
- **PR #33**, ранняя ветка Norsk Eventyr 8.1 с 224 коммитами ahead и 180 behind main (на момент сверки): старое и новое развитие разошлись; критические функции обработки ошибок уже переработаны в 8.2 и проверяются тестом consolidated-intelligence. Полное объединение старой ветки может вернуть устаревшие PWA, доступ и поведение прогресса. Сама ветка сохраняется, её невошедшие идеи можно отдельно переоценить.
- **PR #41**, черновик отдельного Android-проекта DistanceHelp: не относится к релизу Norsk Eventyr.
- Будущие обещанные тысячи аутентичных материалов, 100+ часов записей, загрузка чужого аудио, новый игровой мир: **НЕ реализованы** данным кандидатом и не могут изображаться выпущенными функциями.
- Независимая редактура носителем языка, реальные записи носителей и педагогическая эффективность: **не доказаны**. Синтетические TTS-тексты нельзя называть записями носителей.

## Как собрать локальный архив (на рабочем компьютере после получения репозитория)
1. Перейти на ветку `release/8.3.0-local-staging-20261013`; сверить commit SHA с CI.
2. В каталоге `tests`: `npm ci`, затем `npx playwright install chromium`, затем `npm test` (полный QA и настоящий Chromium).
3. Из корня: `node tools/prepare-staging-release.cjs`.
4. Получить `release-out/norsk-eventyr-8.3.0-source.zip`, `release-out/RELEASE_MANIFEST_8.3.0.json`, `release-out/SHA256SUMS`. SHA256 проверять после переноса.
5. В GitHub Actions релизный архив создаётся автоматически только при полном успешном QA для staging PR (workflow `.github/workflows/qa.yml`); скачиваемые артефакты хранятся ограниченное время.
6. Архив содержит только файлы **закреплённого Git-коммита**, без `.git`, локальных незакоммиченных данных, учётных данных и пользовательских аудиозаписей. Не добавлять реальные оценки учеников в git.

## Блокирующие условия массового запуска — NO-GO пока не закрыты
Основание: `SECURITY_RELEASE_PLAN_8_2.md` и `research/PREMIUM_LEARNING_PROGRAM_2026.md`.
- Не подтверждены реальные production-настройки WAF, лимитов расходов на AI, Supabase security advisor, восстановления аккаунта и всех серверных миграций в изолированной копии.
- Не доказана корректность GDPR-политики фактического хранения/удаления пользовательских данных, договоров с обработчиками и процедуры полного удаления аккаунта.
- Нет профессионального подтверждения B1–B2, независимой проверки точности AI-оценок или разрешённых человеческих аудиозаписей.
- Не проверены все ключевые действия на реальном телефоне именно с версией 8.3.0.
- Нет отдельного разрешения владельца на **слияние с main** и выпуск в Vercel Production.

## Публикация (выполнять ТОЛЬКО после закрытия необходимых пунктов и разрешения владельца)
1. Заново сверить HEAD staging PR и QA/Preview SHA. Проверить отсутствие конфликтов и нежелательных изменений доступа, хранилища и секретов.
2. Подтвердить резервную копию и план возврата на 8.2.9. При наличии новых обязательных SQL-миграций подготовить их до релиза, иначе не менять базу.
3. Получить явное разрешение на production.
4. Слить staging PR с main. Это автоматически запустит деплой в Vercel Production — **не делать заранее**.
5. Дождаться READY с точным merge SHA и зелёного пострелизного QA.
6. Ручной smoke-тест Android, реальная регистрация, микрофон, аудирование, проверка прогресса и удаления/экспорта данных; наблюдение расходов AI. При проблемах использовать документированный откат.

**Оценка:** техническая версия 8.3.0 может быть подготовлена к контролируемому тестированию, но это не экспертное одобрение всей программы, не GDPR-сертификация и не разрешение на массовую коммерческую публикацию.
