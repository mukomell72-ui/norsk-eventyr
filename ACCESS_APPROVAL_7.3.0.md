# Доступ с одобрением владельца — 7.3.0

Обновление подготовлено и локально проверено. 3 октября 2026 UTC миграция `norsk_eventyr_access_approval` применена в Supabase; проверены RLS и запрет анонимного доступа к таблице и одобрениям. Основной сайт остаётся на 7.2.2 до проверки первого входа владельца и отправки почты. Учётная запись владельца при подготовке публикации отсутствовала.

Владелец: **mukomell72@gmail.com**, адрес выбран пользователем. Право владельца определяется на сервере по подтверждённому адресу в Supabase Auth, а не по данным браузера или user_metadata.

Пользователь регистрируется, подтверждает почту, входит и отправляет заявку с именем. Владелец открывает «Настройки → Доступ и учётная запись», одобряет, отказывает или отзывает доступ. До одобрения учебные экраны не загружаются; каждый запрос учебного API, облака и выдачи сессии отдельно проверяет текущий статус. Смена статуса блокирует новые запросы сразу; открытый интерфейс проверяет статус раз в минуту и при возвращении во вкладку. При невозможности проверить доступ приложение закрывает учебный интерфейс. Холодный запуск без интернета требует подключения.

Кнопка установки есть в настройках только доступного учебного приложения и проверяет одобрение заново. Браузер может позволять вручную добавить любой сайт на главный экран: запретить создание такого значка нельзя. Это не даёт доступа к обучению или серверным функциям. Статические файлы не являются DRM-защищённым содержимым; ранее скачанные копии невозможно отозвать.

Учётные записи имеют отдельные ключи прогресса, резервных копий, облачной привязки и временной сессии на одном устройстве. Для владельца прежние локальные данные копируются один раз в его пространство; исходная копия сохраняется. Авторизация хранится в Secure HttpOnly SameSite cookies. Пароли обрабатывает Supabase Auth; приложение не сохраняет их. Существующая таблица облачного прогресса не изменяется.

## Подготовка публикации

1. В проекте Supabase `rskgbkgtrigtznnksbyp` настроить почтовую отправку для внешних пользователей. Стандартная почта Supabase имеет ограничения; проверить собственный SMTP и реальную доставку владельцу и внешнему адресату. Секрет SMTP не хранить в репозитории.
2. Указать Site URL `https://norsk-eventyr-mvp.vercel.app`. В шаблоне **Confirm signup** использовать ссылку `{{ .SiteURL }}/?token_hash={{ .TokenHash }}&type=signup`. Приложение обрабатывает token_hash, обменивает его на HttpOnly cookies и убирает параметр из адреса. Стандартная ссылка с access_token во fragment этим интерфейсом не поддерживается.
3. Применить `migrations/20261003_access_approval.sql` до выкладки сайта. Миграция создаёт только новую таблицу и ограниченные RPC, не изменяя прежнее облачное хранилище. Проверена на локальном PostgreSQL-совместимом PGlite. В действующей базе уже применена при подготовке публикации.
4. До переключения основного домена проверить HTTPS preview: регистрацию и подтверждение владельца, вход, внешнюю заявку, одобрение, получение учебного API, отзыв и сохранность старого прогресса. Не выдавать пароль владельца третьим лицам. Автоматические тесты не подтверждают реальную доставку почты.
5. Публиковать одним обновлением только после отдельной команды пользователя. При ошибке конфигурации защита закрывает доступ, а не допускает незарегистрированных пользователей. Старый сайт 7.2.2 до публикации продолжает работать.

## Проверка

`tests/access-api.mjs`: проверка почты, статусов, прав владельца, обновления cookies, ошибок, выхода и origin.

`tests/access-sql.cjs`: выполнение настоящей миграции в PGlite, запрет самостоятельного одобрения, запрет прямого доступа к таблице и анонимных RPC, сохранение отказа/отзыва при повторной заявке.

`tests/access-browser.cjs`: интерфейс входа и заявки, список владельца, экранирование имени, одобрение/отзыв, миграция владельца и отдельный прогресс двух учётных записей на одном устройстве. Auth и API в этом тесте имитируются.

Существующие проверки уроков, облачных слияний, асинхронного аудио, 20 маршрутов и обновления двух установленных экземпляров сохранены. Тест холодного offline запуска обновлён под обязательную серверную проверку доступа.

Авторизация использует действия внутри существующего `/api/session`; обычная выдача учебной сессии по-прежнему требует одобрения. Это сохраняет 12 развёртываемых серверных функций. Первая тестовая сборка с отдельной 13-й функцией завершилась ошибкой; маршрут объединён и повторно проверен.
