# Norsk Eventyr — формы профессиональной проверки и пилота
Статус: шаблоны процесса, **не проведённая экспертиза и не набор реальных записей**.

## 1. Карточка редактора для каждого модуля
Заполняет реальный квалифицированный преподаватель/редактор Bokmål на конкретную версию контента.

| Поле | Требование |
| --- | --- |
| module_id / revision | Неизменяемый ID и хеш/номер редакции |
| CEFR + can-do | Соответствие заявленной цели, источник дескриптора HK-dir/CEFR |
| Norwegian grammar | Правильный V2, формы глагола, определённость, предлоги, связность |
| Lexical register | Разговорное, официальное, региональное; объяснить, почему уместно |
| Task fidelity | Вопрос проверяет ИМЕННО содержание данного текста/записи; нет двусмысленных ключей |
| Wrong choices | Дистракторы неверны по смыслу, но правдоподобны; нет повторов |
| Translation | Перевод верен; в заданиях с переводом по запросу не раскрывает ответ заранее |
| Productive skills | Есть самостоятельное говорение/письмо и новое уточнение; аудиозапись не заменяется напечатанным ответом |
| Accessibility | Транскрипт, доступ к кнопкам, скорость и подсказка не лишают смысла контроль |
| Verdict | draft → needs_changes → reviewed → approved. Автор и редактор не могут совпадать при независимой экспертизе |
| Proof | Дата, анонимный ID редактора, квалификация, комментарии, версия, идентификатор подтверждения |

Два независимых специалиста проверяют спорные места. Не записывать «проверено носителем» до подтверждения; при пересборке смыслового вопроса требуется повторное утверждение.

## 2. Карточка аудиоматериала и права
Минимальный формат: id; source_type (human_recording / synthetic_tts / user_private_upload); level; language (nb-NO либо проверенная диалектная разновидность); text_revision; transcript; duration_seconds; speaker_count; speed; accents; content_license; owner_consent_reference; recording_release_reference; editorial_approval_reference; allowed_uses; retention; removal_process; source_url (если лицензия разрешает); provenance_status.

Применять правила:
- «Реальная речь» — только подтверждённая запись человека, а не смена AI-голоса.
- Для опубликованной записи нужны разрешение говорящего и право на распространение/переработку, включая коммерческий вариант, если он предусмотрен.
- Пользовательские аудиофайлы по умолчанию доступны только самому пользователю. Импорт не означает передачу их в общую библиотеку.
- Условно свободный онлайн-доступ ≠ лицензия. Без доказанных прав файл не включается в релиз.
- При отсутствии данных прав отображать явно «источник и права не подтверждены», не маркировать как проверенный.

## 3. Подготовка независимого оценки AI
Универсальная шкала 0–100 — лишь внутренняя метрика, её соответствие официальному CEFR необходимо доказать.
- Сначала преподаватели согласуют рубрику для каждого навыка/уровня на примерах.
- Для письма отдельно оценивать выполнение задачи, понятность, связность, грамматику и лексику.
- Для говорения отдельно коммуникативную успешность и понятность; ASR-расшифровка не является оценкой произношения.
- Два эксперта оценивают ответы независимо, не видя AI-оценку и не зная экспериментальную группу; существенное расхождение требует третьей оценки.
- Создавать отдельную тестовую выборку, не пересекающуюся с примерами в AI-промптах.
- Публиковать ошибки оценки (MAE, смещение вверх/вниз, частоту больших разногласий) с размером выборки и диапазоном неопределённости; по уровням и навыкам отдельно.
- Инструмент tools/assessment-calibration.cjs выполняет подсчёт ТОЛЬКО на локальном JSON с id/level/skill/expert_1/expert_2/ai_score. Он не подтверждает квалификацию рецензентов или полноту выборки.

Минимальный пример формата (значения демонстрационные, не данные учеников):
```json
{"items":[{"id":"anon-001","level":"A2","skill":"writing","expert_1":75,"expert_2":78,"ai_score":80}]}
```
Команда локально: `node tools/assessment-calibration.cjs /PRIVATE/PATH/anon-scores.json`. Не коммитить настоящий файл результатов в GitHub, не включать имя, электронную почту, исходный текст или аудиозапись.

## 4. Протокол исследования индивидуальной адаптации
**Цель:** проверить, улучшает ли выбор следующей миссии Норой независимый учебный результат относительно фиксированного учебного маршрута, при равном времени.
- Перед набором: выбрать основную метрику (например, прирост на новой коммуникативной задаче через 30 дней), план анализа и объём выборки по мощности. Замена критериев после просмотра результатов недопустима.
- Набрать добровольцев от 18 лет, пояснить срок, использование данных, право отказаться, недопустимость гарантии результата.
- Стратифицировать по стартовому A1–B2 и слабым навыкам; распределение по группам случайное. Оценщикам не сообщать, какой маршрут использовал ученик.
- Группа A: персональный следующий урок. Группа B: эквивалентное количество минут и материалов, но фиксированный порядок; обе группы имеют равный доступ к качественному преподавательскому содержанию и помощи.
- Замеры: до обучения, сразу после, 7, 30 и 90 дней. Незнакомые задания, не копирующие уроки.
- Учесть начало/окончание курса, пропуски, помощь вне приложения, исходный уровень, время работы AI и расходы; анализировать выбывших и тех, кто дошёл до конца, не маскировать уходящих.
- Малый пилот (ориентир 10–20 человек) нужен для проверки интерфейса/процедуры, **не доказательства превосходства**. Значимый эффект потребует большего исследования и статистического плана.

**Приватность:** согласие, минимизация данных, разграничение доступа, срок хранения/удаления, отдельный порядок для аудио и голосовых данных, актуальные условия обработчиков. Ничего не собирать тайно.

## 5. Приёмка игрового опыта
Новые механики должны повышать вероятность самостоятельной коммуникации, а не только удержание.
- Есть задания без подсказки, понятные ошибочные ответы, доступная клавиатура/экранный диктор, возможность отключить игровые уведомления.
- Очки не открывают B2; статус навыка получает подтверждение только от соответствующей независимой проверки.
- Измерять 7/30-дневное возвращение вместе с учебным прогрессом и жалобами; не применять скрытых штрафов за пропуск, навязчивых механик и ложных достижений.

## 6. Стоп-условия публикации
Не выпускать изменения в обучение при несовпадении вопроса и оценивания, потере прогресса, ложном подтверждении устного навыка, неясных правах на запись, непроверенном хранении личных данных или наличии красных ошибок в CI. Вся разработка в отдельных PR, публикация по разрешению владельца.
